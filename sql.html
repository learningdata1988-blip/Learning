1.1SELECT, Filtering, Sorting & NULL

-- Basic shape
SELECT DISTINCT dept_id, salary * 12 AS annual_salary
FROM   employees
WHERE  salary >= 80000
  AND  hire_date BETWEEN '2020-01-01' AND '2022-12-31'
  AND  name LIKE 'A%'                 -- % any chars, _ one char
  AND  dept_id IN (10, 20)
ORDER BY annual_salary DESC, name ASC
LIMIT 10;                             -- SQL Server: SELECT TOP 10 ... | Oracle: FETCH FIRST 10 ROWS ONLY

-- NULL rules: NULL is "unknown", never equal to anything (even NULL)
SELECT * FROM employees WHERE manager_id IS NULL;         -- correct
SELECT * FROM employees WHERE manager_id = NULL;          -- returns nothing!
SELECT name, COALESCE(dept_id, -1) AS dept FROM employees;   -- first non-null
SELECT NULLIF(salary, 0) FROM employees;                  -- avoid divide-by-zero
SELECT name FROM employees WHERE dept_id NOT IN (10, NULL);  -- returns NOTHING (NULL trap)
NULL trapsNOT IN with a NULL in the list returns no rows – use NOT EXISTS instead. COUNT(col) ignores NULLs; COUNT(*) does not. Aggregates (SUM/AVG/MAX) ignore NULLs. Comparison with NULL yields UNKNOWN, which WHERE treats as false.

1.2Logical Order of Execution

SQL is written SELECT → FROM but evaluated in a different order. This explains why you can't use a SELECT alias in WHERE.

1. FROM / JOIN build the row source 2. WHERE filter rows (no aggregates, no select aliases) 3. GROUP BY form groups 4. HAVING filter groups (aggregates allowed) 5. SELECT compute expressions, window functions, aliases 6. DISTINCT remove duplicates 7. ORDER BY sort (can use aliases) 8. LIMIT / TOP trim result

JoinReturns

FULL OUTER JOINAll rows from both; NULLs where unmatched (not in MySQL)

-- Inner: employees with their department name
SELECT e.name, d.dept_name
FROM   employees e
JOIN   departments d ON d.dept_id = e.dept_id;          -- Eli (NULL dept) is dropped

-- Left: keep everyone, even without a department
SELECT e.name, d.dept_name
FROM   employees e
LEFT JOIN departments d ON d.dept_id = e.dept_id;

-- Anti join: departments with no employees (HR)
SELECT d.*
FROM   departments d
LEFT JOIN employees e ON e.dept_id = d.dept_id
WHERE  e.emp_id IS NULL;

-- Self join: employee with manager name
SELECT e.name AS employee, m.name AS manager
FROM   employees e
LEFT JOIN employees m ON m.emp_id = e.manager_id;

-- Full outer: reconcile two sources
SELECT COALESCE(a.id, b.id) AS id, a.val AS a_val, b.val AS b_val
FROM   src_a a FULL OUTER JOIN src_b b ON a.id = b.id
WHERE  a.id IS NULL OR b.id IS NULL OR a.val <> b.val;
LEFT JOIN trapA filter on the right table in WHERE silently turns a LEFT JOIN into an INNER JOIN. Put it in the ON clause instead: LEFT JOIN orders o ON o.customer_id = c.customer_id AND o.status = 'DONE'.
Join fan-outJoining on a non-unique key multiplies rows and inflates SUM/COUNT. Check cardinality (1:1, 1:N, M:N) before joining, and aggregate before joining when needed.

2.1Aggregation: GROUP BY & HAVING

SELECT   dept_id,
         COUNT(*)              AS headcount,
         COUNT(manager_id)     AS with_manager,       -- ignores NULLs
         COUNT(DISTINCT salary) AS distinct_salaries,
         SUM(salary)           AS payroll,
         AVG(salary)           AS avg_salary,
         MIN(hire_date)        AS first_hire,
         MAX(salary)           AS top_salary
FROM     employees
WHERE    hire_date >= '2020-01-01'      -- filters ROWS before grouping
GROUP BY dept_id
HAVING   COUNT(*) > 1                  -- filters GROUPS after aggregation
ORDER BY payroll DESC;

-- Conditional aggregation (pivot-style)
SELECT customer_id,
       SUM(CASE WHEN status = 'DONE'      THEN amount ELSE 0 END) AS done_amt,
       SUM(CASE WHEN status = 'CANCELLED' THEN amount ELSE 0 END) AS cancelled_amt,
       COUNT(*) FILTER (WHERE status = 'DONE') AS done_orders   -- PostgreSQL / Spark; else use CASE
FROM   orders
GROUP BY customer_id;

-- Subtotals
SELECT dept_id, manager_id, SUM(salary) FROM employees GROUP BY ROLLUP (dept_id, manager_id);
-- also CUBE (...) and GROUPING SETS ((a),(b),())
RuleEvery non-aggregated column in SELECT must appear in GROUP BY (MySQL may allow otherwise, but results are undefined).

3Subqueries & CTEs

-- Scalar subquery
SELECT name, salary, salary - (SELECT AVG(salary) FROM employees) AS diff_from_avg
FROM employees;

-- IN / EXISTS (EXISTS short-circuits and is NULL-safe)
SELECT * FROM customers c
WHERE EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.customer_id AND o.status = 'DONE');

-- Correlated subquery: employees paid above their department average
SELECT e.name, e.salary
FROM   employees e
WHERE  e.salary > (SELECT AVG(salary) FROM employees WHERE dept_id = e.dept_id);

-- Derived table
SELECT dept_id, avg_sal FROM (SELECT dept_id, AVG(salary) AS avg_sal FROM employees GROUP BY dept_id) t
WHERE avg_sal > 80000;

-- CTE: readable, reusable within one statement
WITH dept_avg AS (
    SELECT dept_id, AVG(salary) AS avg_sal FROM employees GROUP BY dept_id
), high AS (
    SELECT e.* FROM employees e JOIN dept_avg d USING (dept_id) WHERE e.salary > d.avg_sal
)
SELECT * FROM high;

-- Recursive CTE: org chart / hierarchy
WITH RECURSIVE org AS (
    SELECT emp_id, name, manager_id, 1 AS lvl FROM employees WHERE manager_id IS NULL   -- anchor
    UNION ALL
    SELECT e.emp_id, e.name, e.manager_id, o.lvl + 1
    FROM   employees e JOIN org o ON e.manager_id = o.emp_id                          -- recursion
)
SELECT * FROM org ORDER BY lvl;       -- SQL Server / Oracle: omit the word RECURSIVE

3.1Window Functions

Windows compute over a set of related rows without collapsing them. Syntax: func() OVER (PARTITION BY … ORDER BY … frame).

SELECT name, dept_id, salary,
       ROW_NUMBER() OVER w AS rn,         -- 1,2,3,4  unique
       RANK()       OVER w AS rnk,        -- 1,1,3,4  gaps after ties
       DENSE_RANK() OVER w AS drnk,       -- 1,1,2,3  no gaps
       NTILE(4)     OVER w AS quartile,
       LAG(salary)  OVER (PARTITION BY dept_id ORDER BY hire_date)     AS prev_salary,
       LEAD(salary, 1, 0) OVER (PARTITION BY dept_id ORDER BY hire_date) AS next_salary,
       FIRST_VALUE(name) OVER w AS top_earner,
       SUM(salary) OVER (PARTITION BY dept_id)                          AS dept_total,
       salary * 1.0 / SUM(salary) OVER (PARTITION BY dept_id)           AS pct_of_dept
FROM employees
WINDOW w AS (PARTITION BY dept_id ORDER BY salary DESC);     -- named window (not in SQL Server)

-- Running total and moving average (frames)
SELECT order_date, amount,
       SUM(amount) OVER (ORDER BY order_date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS running_total,
       AVG(amount) OVER (ORDER BY order_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)         AS moving_avg_7
FROM orders;
RememberWindow functions run after WHERE/GROUP BY/HAVING, so you can't filter on them directly. Wrap in a CTE/subquery: WITH r AS (SELECT …, ROW_NUMBER() OVER … rn FROM t) SELECT * FROM r WHERE rn = 1. (Snowflake/BigQuery/Databricks also support QUALIFY.) With ORDER BY and no frame, the default frame is RANGE UNBOUNDED PRECEDING … CURRENT ROW – ties get the same running total.

3.2String, Date & CASE Functions

-- CASE
SELECT name,
       CASE WHEN salary >= 120000 THEN 'High'
            WHEN salary >=  80000 THEN 'Mid'
            ELSE 'Low' END AS band
FROM employees;

-- Strings (PostgreSQL / standard-ish)
SELECT UPPER(name), LOWER(name), LENGTH(name), TRIM('  x  '),
       SUBSTRING(name FROM 1 FOR 3),      -- MySQL/SQL Server: SUBSTRING(name,1,3)
       CONCAT(name, '-', dept_id),        -- or name || '-' || dept_id
       REPLACE(name, 'a', '@'),
       POSITION('s' IN name),             -- SQL Server: CHARINDEX('s', name)
       LEFT(name, 2), RIGHT(name, 2),
       STRING_AGG(name, ', ')             -- MySQL: GROUP_CONCAT(name SEPARATOR ', ')
FROM employees GROUP BY name;

-- Dates (PostgreSQL)
SELECT CURRENT_DATE, NOW(),
       EXTRACT(YEAR FROM hire_date)  AS yr,
       DATE_TRUNC('month', hire_date) AS month_start,
       hire_date + INTERVAL '30 days' AS plus_30,
       CURRENT_DATE - hire_date       AS days_employed,     -- integer days
       TO_CHAR(hire_date, 'YYYY-MM')  AS ym
FROM employees;
-- MySQL: DATE_ADD(d, INTERVAL 30 DAY), DATEDIFF(a,b), DATE_FORMAT(d,'%Y-%m')
-- SQL Server: DATEADD(day,30,d), DATEDIFF(day,a,b), FORMAT(d,'yyyy-MM'), EOMONTH(d)
-- Spark SQL: date_add(d,30), datediff(a,b), date_format(d,'yyyy-MM'), trunc(d,'MM')

5Indexes & Query Performance

CREATE INDEX idx_orders_cust_date ON orders (customer_id, order_date);   -- composite: leftmost-prefix rule
CREATE UNIQUE INDEX uq_emp_email ON employees (email);

EXPLAIN SELECT * FROM orders WHERE customer_id = 1;            -- plan only
EXPLAIN ANALYZE SELECT * FROM orders WHERE customer_id = 1;    -- executes + real timings (PostgreSQL)

Index types

  • Clustered (SQL Server/InnoDB): table rows are physically stored in index order – one per table (usually the PK).
  • Non-clustered / secondary: separate B-tree pointing to rows – many per table.
  • Covering index: contains all columns a query needs (index-only scan).
  • Others: hash, bitmap, full-text, partial/filtered, columnstore.

Writing index-friendly (SARGable) queries

-- BAD: function on the indexed column blocks the index
WHERE YEAR(order_date) = 2025
WHERE UPPER(name) = 'ASHA'
WHERE amount + 10 > 100
WHERE name LIKE '%sha'                    -- leading wildcard

-- GOOD
WHERE order_date >= '2025-01-01' AND order_date < '2026-01-01'
WHERE name = 'Asha'                       -- or a functional index on UPPER(name)
WHERE amount > 90
WHERE name LIKE 'As%'
Slow query checklist
  1. Read the plan (EXPLAIN): look for full table scans, big sorts, nested loops over large sets.
  2. Select only needed columns; avoid SELECT *.
  3. Filter early; make predicates SARGable; check data types match (implicit casts kill indexes).
  4. Index join and filter columns (but every index slows writes).
  5. Replace correlated subqueries with joins/windows; prefer EXISTS over IN for large sets; UNION ALL over UNION.
  6. Update statistics, consider partitioning for huge tables, paginate with keyset instead of big OFFSET.

5.2Stored Procedures: Overview

A stored procedure is a named, precompiled block of SQL and procedural code saved in the database. You call it by name with parameters. Typical uses: ETL/batch steps, business rules that must run next to the data, controlled data access (grant EXECUTE without table access), and reducing round trips.

BenefitTrade-off
Fewer network round trips; plan caching and reuseBusiness logic lives in the DB – harder to version, test and debug
Security: grant EXECUTE only, helps prevent SQL injection when parameterizedVendor-specific syntax (T-SQL vs PL/SQL) – poor portability
Centralized logic reused by many apps; atomic multi-statement transactionsRow-by-row cursor loops are slow – prefer set-based SQL

5.3Stored Procedures in SQL Server (T-SQL)

1. Basic procedure with parameters

CREATE OR ALTER PROCEDURE dbo.usp_GetEmployeesByDept     -- CREATE OR ALTER: SQL Server 2016 SP1+
    @DeptId    INT,
    @MinSalary DECIMAL(12,2) = 0                         -- default value makes it optional
AS
BEGIN
    SET NOCOUNT ON;                                      -- suppress "n rows affected" chatter

    SELECT emp_id, name, salary, hire_date
    FROM   dbo.employees
    WHERE  dept_id = @DeptId
      AND  salary >= @MinSalary
    ORDER BY salary DESC;
END
GO

EXEC dbo.usp_GetEmployeesByDept @DeptId = 10;                        -- named params (preferred)
EXEC dbo.usp_GetEmployeesByDept 20, 80000;                           -- positional

2. OUTPUT parameters and return codes

CREATE OR ALTER PROCEDURE dbo.usp_GetDeptStats
    @DeptId     INT,
    @Headcount  INT           OUTPUT,
    @AvgSalary  DECIMAL(12,2) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    SELECT @Headcount = COUNT(*), @AvgSalary = AVG(salary)
    FROM   dbo.employees WHERE dept_id = @DeptId;

    IF @Headcount = 0 RETURN -1;       -- RETURN gives an INTEGER status code only
    RETURN 0;
END
GO

DECLARE @cnt INT, @avg DECIMAL(12,2), @rc INT;
EXEC @rc = dbo.usp_GetDeptStats @DeptId = 10, @Headcount = @cnt OUTPUT, @AvgSalary = @avg OUTPUT;
SELECT @rc AS return_code, @cnt AS headcount, @avg AS avg_salary;

3. Transaction + TRY…CATCH error handling (production template)

CREATE OR ALTER PROCEDURE dbo.usp_TransferSalaryBudget
    @FromDept INT, @ToDept INT, @Amount DECIMAL(12,2)
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;                                   -- any runtime error rolls back the whole txn

    BEGIN TRY
        BEGIN TRANSACTION;

        UPDATE dbo.dept_budget SET budget = budget - @Amount WHERE dept_id = @FromDept;
        IF @@ROWCOUNT = 0 THROW 50001, 'Source department not found.', 1;

        UPDATE dbo.dept_budget SET budget = budget + @Amount WHERE dept_id = @ToDept;
        IF @@ROWCOUNT = 0 THROW 50002, 'Target department not found.', 1;

        COMMIT TRANSACTION;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK TRANSACTION;

        INSERT INTO dbo.error_log (proc_name, err_no, err_msg, err_line, logged_at)
        VALUES (ERROR_PROCEDURE(), ERROR_NUMBER(), ERROR_MESSAGE(), ERROR_LINE(), SYSDATETIME());

        THROW;                                           -- re-raise to the caller
    END CATCH
END
GO

4. Upsert procedure (insert or update)

CREATE OR ALTER PROCEDURE dbo.usp_UpsertEmployee
    @EmpId INT, @Name NVARCHAR(100), @Salary DECIMAL(12,2), @DeptId INT
AS
BEGIN
    SET NOCOUNT ON;
    BEGIN TRY
        BEGIN TRAN;
        MERGE dbo.employees AS t
        USING (SELECT @EmpId AS emp_id, @Name AS name, @Salary AS salary, @DeptId AS dept_id) AS s
           ON t.emp_id = s.emp_id
        WHEN MATCHED THEN UPDATE SET name = s.name, salary = s.salary, dept_id = s.dept_id
        WHEN NOT MATCHED THEN INSERT (emp_id, name, salary, dept_id) VALUES (s.emp_id, s.name, s.salary, s.dept_id);
        COMMIT;
    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;
        THROW;
    END CATCH
END
GO

5. Control flow, temp tables, loops

CREATE OR ALTER PROCEDURE dbo.usp_GiveRaises @Pct DECIMAL(5,2)
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @updated INT = 0;

    IF @Pct <= 0 OR @Pct > 50
    BEGIN
        RAISERROR('Raise percentage out of range.', 16, 1);   -- or THROW 50003, '...', 1;
        RETURN;
    END

    CREATE TABLE #raised (emp_id INT, old_salary DECIMAL(12,2), new_salary DECIMAL(12,2));   -- temp table, session scoped

    UPDATE e
       SET salary = salary * (1 + @Pct / 100.0)
    OUTPUT inserted.emp_id, deleted.salary, inserted.salary INTO #raised     -- capture changes
    FROM dbo.employees e
    WHERE e.dept_id IS NOT NULL;

    SET @updated = @@ROWCOUNT;

    SELECT @updated AS rows_updated;
    SELECT TOP 5 * FROM #raised ORDER BY new_salary DESC;
    DROP TABLE #raised;
END
GO

-- WHILE loop (use sparingly; set-based is usually better)
DECLARE @i INT = 1;
WHILE @i <= 3 BEGIN PRINT CONCAT('Iteration ', @i); SET @i += 1; END

6. Dynamic SQL (safe, parameterized)

CREATE OR ALTER PROCEDURE dbo.usp_SearchEmployees
    @SortColumn SYSNAME = 'name', @MinSalary DECIMAL(12,2) = 0
AS
BEGIN
    SET NOCOUNT ON;
    -- Whitelist identifiers: they can't be parameterized
    IF @SortColumn NOT IN ('name', 'salary', 'hire_date') THROW 50010, 'Invalid sort column', 1;

    DECLARE @sql NVARCHAR(MAX) =
        N'SELECT emp_id, name, salary FROM dbo.employees WHERE salary >= @p_min ORDER BY ' + QUOTENAME(@SortColumn);

    EXEC sys.sp_executesql @sql, N'@p_min DECIMAL(12,2)', @p_min = @MinSalary;   -- values stay parameters
END
GO

7. Cursor (row-by-row) and table-valued parameter

-- Cursor: only when logic truly can't be set-based
DECLARE @id INT, @name NVARCHAR(100);
DECLARE c CURSOR LOCAL FAST_FORWARD FOR SELECT emp_id, name FROM dbo.employees;
OPEN c;
FETCH NEXT FROM c INTO @id, @name;
WHILE @@FETCH_STATUS = 0
BEGIN
    PRINT CONCAT(@id, ' - ', @name);
    FETCH NEXT FROM c INTO @id, @name;
END
CLOSE c; DEALLOCATE c;

CREATE TYPE dbo.EmpIdList AS TABLE (emp_id INT PRIMARY KEY);
GO

AS

5.4Stored Procedures in Oracle (PL/SQL)

1. Basic procedure with IN / OUT parameters

CREATE OR REPLACE PROCEDURE get_dept_stats (
    p_dept_id   IN  employees.dept_id%TYPE,          -- %TYPE copies the column's data type
    p_headcount OUT NUMBER,
    p_avg_sal   OUT NUMBER
)
IS                                                    -- declaration section (IS or AS)
    v_max_sal employees.salary%TYPE;
BEGIN
    SELECT COUNT(*), AVG(salary), MAX(salary)
    INTO   p_headcount, p_avg_sal, v_max_sal
    FROM   employees
    WHERE  dept_id = p_dept_id;

    DBMS_OUTPUT.PUT_LINE('Dept ' || p_dept_id || ' max salary: ' || v_max_sal);
END get_dept_stats;
/

-- Call it from an anonymous block (or SQL*Plus: EXEC procedure_name(...))
SET SERVEROUTPUT ON
DECLARE
    v_cnt NUMBER; v_avg NUMBER;
BEGIN
    get_dept_stats(10, v_cnt, v_avg);
    DBMS_OUTPUT.PUT_LINE('Headcount=' || v_cnt || ', avg=' || ROUND(v_avg, 2));
    get_dept_stats(p_dept_id => 20, p_headcount => v_cnt, p_avg_sal => v_avg);   -- named notation
END;
/
Parameter modesIN (default, read-only), OUT (returns a value), IN OUT (passed in and modified). Add DEFAULT to make a parameter optional. The trailing / on its own line executes the block in SQL*Plus / SQL Developer scripts.

2. Exception handling and transactions

CREATE OR REPLACE PROCEDURE transfer_budget (
    p_from IN NUMBER, p_to IN NUMBER, p_amount IN NUMBER
)
IS
    e_insufficient EXCEPTION;
    PRAGMA EXCEPTION_INIT(e_insufficient, -20001);
    v_balance dept_budget.budget%TYPE;
BEGIN
    SELECT budget INTO v_balance FROM dept_budget WHERE dept_id = p_from FOR UPDATE;   -- lock the row

    IF v_balance < p_amount THEN
        RAISE_APPLICATION_ERROR(-20001, 'Insufficient budget in department ' || p_from);   -- -20000..-20999
    END IF;

    UPDATE dept_budget SET budget = budget - p_amount WHERE dept_id = p_from;
    UPDATE dept_budget SET budget = budget + p_amount WHERE dept_id = p_to;

    IF SQL%ROWCOUNT = 0 THEN                        -- rows affected by the last DML
        RAISE_APPLICATION_ERROR(-20002, 'Target department not found');
    END IF;

    COMMIT;
EXCEPTION
    WHEN NO_DATA_FOUND THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20003, 'Source department not found');
    WHEN TOO_MANY_ROWS THEN
        ROLLBACK; RAISE;
    WHEN OTHERS THEN
        ROLLBACK;
        INSERT INTO error_log (proc_name, err_code, err_msg, logged_at)
        VALUES ('transfer_budget', SQLCODE, SUBSTR(SQLERRM, 1, 4000), SYSTIMESTAMP);
        COMMIT;                                      -- keep the log row (or use an autonomous transaction)
        RAISE;                                       -- re-raise to the caller
END transfer_budget;
/

3. Cursors: explicit, FOR loop and returning a result set

CREATE OR REPLACE PROCEDURE print_high_earners (p_min IN NUMBER)
IS
    CURSOR c_emp IS SELECT emp_id, name, salary FROM employees WHERE salary >= p_min ORDER BY salary DESC;
BEGIN
    FOR r IN c_emp LOOP                              -- implicit open / fetch / close
        DBMS_OUTPUT.PUT_LINE(r.emp_id || ' ' || r.name || ' ' || r.salary);
    END LOOP;
END;
/

-- Return a result set to a client (like SELECT from a T-SQL procedure)
CREATE OR REPLACE PROCEDURE get_employees (p_dept IN NUMBER, p_rc OUT SYS_REFCURSOR)
IS
BEGIN
    OPEN p_rc FOR SELECT emp_id, name, salary FROM employees WHERE dept_id = p_dept;
END;
/

4. Bulk processing (BULK COLLECT / FORALL) – the fast way

CREATE OR REPLACE PROCEDURE give_raise_bulk (p_dept IN NUMBER, p_pct IN NUMBER)
IS
    TYPE t_ids IS TABLE OF employees.emp_id%TYPE;
    v_ids t_ids;
BEGIN
    SELECT emp_id BULK COLLECT INTO v_ids FROM employees WHERE dept_id = p_dept;   -- one fetch into memory

    FORALL i IN 1 .. v_ids.COUNT                                                   -- one DML round trip for all rows
        UPDATE employees SET salary = salary * (1 + p_pct / 100) WHERE emp_id = v_ids(i);

    DBMS_OUTPUT.PUT_LINE(SQL%ROWCOUNT || ' rows updated');
    COMMIT;
END;
/
-- Row-by-row loops with DML inside cause "context switches" between PL/SQL and SQL engines – avoid.
-- For huge sets use BULK COLLECT ... LIMIT 1000 in a loop, or a single set-based UPDATE.

5. Upsert, dynamic SQL, function and trigger

CREATE OR REPLACE PROCEDURE upsert_employee (
    p_id IN NUMBER, p_name IN VARCHAR2, p_salary IN NUMBER, p_dept IN NUMBER
)
IS
BEGIN
    MERGE INTO employees t
    USING (SELECT p_id AS emp_id, p_name AS name, p_salary AS salary, p_dept AS dept_id FROM dual) s
       ON (t.emp_id = s.emp_id)
    WHEN MATCHED THEN UPDATE SET t.name = s.name, t.salary = s.salary, t.dept_id = s.dept_id
    WHEN NOT MATCHED THEN INSERT (emp_id, name, salary, dept_id) VALUES (s.emp_id, s.name, s.salary, s.dept_id);
    COMMIT;
END;
/

-- Dynamic SQL with bind variables (prevents injection and enables plan reuse)
CREATE OR REPLACE PROCEDURE count_by_status (p_table IN VARCHAR2, p_status IN VARCHAR2, p_count OUT NUMBER)
IS
BEGIN
    EXECUTE IMMEDIATE 'SELECT COUNT(*) FROM ' || DBMS_ASSERT.SQL_OBJECT_NAME(p_table) || ' WHERE status = :1'
        INTO p_count USING p_status;
END;
/

-- Function: usable inside SELECT
CREATE OR REPLACE FUNCTION annual_salary (p_monthly IN NUMBER) RETURN NUMBER
IS BEGIN RETURN p_monthly * 12; END;
/
SELECT name, annual_salary(salary) FROM employees;

-- Row-level trigger
CREATE OR REPLACE TRIGGER trg_emp_audit
AFTER UPDATE OF salary ON employees
FOR EACH ROW
BEGIN
    INSERT INTO salary_audit (emp_id, old_salary, new_salary, changed_at)
    VALUES (:OLD.emp_id, :OLD.salary, :NEW.salary, SYSDATE);
END;
/

6. Packages – group related procedures

-- Specification (public interface)
CREATE OR REPLACE PACKAGE emp_pkg AS
    c_max_raise CONSTANT NUMBER := 20;
    PROCEDURE give_raise (p_emp_id IN NUMBER, p_pct IN NUMBER);
    FUNCTION  get_salary (p_emp_id IN NUMBER) RETURN NUMBER;
END emp_pkg;
/
-- Body (implementation, may contain private helpers)
CREATE OR REPLACE PACKAGE BODY emp_pkg AS
    PROCEDURE give_raise (p_emp_id IN NUMBER, p_pct IN NUMBER) IS
    BEGIN
        IF p_pct > c_max_raise THEN RAISE_APPLICATION_ERROR(-20010, 'Raise too large'); END IF;
        UPDATE employees SET salary = salary * (1 + p_pct / 100) WHERE emp_id = p_emp_id;
    END;

    FUNCTION get_salary (p_emp_id IN NUMBER) RETURN NUMBER IS v NUMBER;
    BEGIN SELECT salary INTO v FROM employees WHERE emp_id = p_emp_id; RETURN v; END;
END emp_pkg;
/
EXEC emp_pkg.give_raise(2, 10);

-- Inspect / compile problems
SELECT * FROM user_source WHERE name = 'EMP_PKG' ORDER BY type, line;

DROP PROCEDURE get_dept_stats;
GRANT EXECUTE ON emp_pkg TO reporting_user;
PL/SQL best practicesPrefer set-based SQL; use BULK COLLECT/FORALL when loops are unavoidable; use bind variables in dynamic SQL; never swallow errors with a bare WHEN OTHERS THEN NULL; use %TYPE/%ROWTYPE so code adapts to schema changes; group related code in packages; remember DDL commits implicitly in Oracle and SELECT INTO must return exactly one row.

What is a stored procedure and why use one?
A named, precompiled set of SQL/procedural statements stored in the database and run with parameters. Benefits: performance (plan reuse, fewer round trips), security (grant EXECUTE only), reuse and centralized logic, and atomic multi-step transactions.
Procedure vs function – what are the differences?
A function must return a value and can be used inside a SELECT/WHERE; a procedure is called as a statement, can return zero or many values (OUT params/result sets), and can freely run DML and manage transactions. SQL Server functions can't perform side-effecting DML; Oracle functions with DML can't be called from SQL queries.
How do you return data from a procedure in SQL Server vs Oracle?
SQL Server: end the procedure with a SELECT (result set), use OUTPUT parameters for scalars, and RETURN only for an integer status. Oracle: use OUT parameters or a SYS_REFCURSOR for result sets.
How do you handle errors in a procedure?
SQL Server: BEGIN TRY … END TRY BEGIN CATCH … END CATCH with XACT_ABORT ON, roll back if @@TRANCOUNT > 0, log via ERROR_MESSAGE() and re-raise with THROW. Oracle: an EXCEPTION block with specific handlers (NO_DATA_FOUND, TOO_MANY_ROWS, WHEN OTHERS), user errors via RAISE_APPLICATION_ERROR, and RAISE to propagate.
What is SET NOCOUNT ON and why use it?
It stops SQL Server from sending "n rows affected" messages for each statement, cutting network chatter and avoiding confusion in client libraries (e.g. ADO.NET) that read the first result.
What is parameter sniffing?
SQL Server compiles a plan using the first parameter values it sees and reuses it. If later values have very different data distributions the cached plan may be poor. Fixes: OPTION (RECOMPILE), OPTIMIZE FOR, local variables, or splitting the procedure by case.
How do you prevent SQL injection in procedures?
Use parameters, not string concatenation. For dynamic SQL use sp_executesql with parameters (SQL Server) or EXECUTE IMMEDIATE … USING bind variables (Oracle); whitelist identifiers and quote them with QUOTENAME / DBMS_ASSERT.
What is a package in Oracle and why use it?
A package bundles related procedures, functions, types and variables into a specification (public API) and a body (implementation). It enables encapsulation, overloading, session-level state, and loads into memory once, improving performance and organization.
Why are cursors/loops slow, and what's the alternative?
Row-by-row processing (RBAR – "row by agonizing row") pays per-row overhead and, in Oracle, repeated PL/SQL↔SQL context switches. Prefer a single set-based statement; in Oracle use BULK COLLECT + FORALL; in SQL Server prefer set-based updates, table-valued parameters and MERGE.
Explain IN, OUT and IN OUT parameters (Oracle) and OUTPUT parameters (SQL Server).
Oracle: IN passes a value in (read-only), OUT returns a value, IN OUT does both. SQL Server parameters are input by default; add OUTPUT to return a value to the caller (it is effectively IN OUT).
How do you view, change or troubleshoot a stored procedure?
SQL Server: sp_helptext, OBJECT_DEFINITION(), sys.sql_modules; modify with ALTER PROCEDURE. Oracle: USER_SOURCE for source, USER_ERRORS/SHOW ERRORS for compile errors; modify with CREATE OR REPLACE. Check plans with the execution plan / DBMS_XPLAN.
Can a stored procedure call another procedure? Can it be recursive?
Yes to both. SQL Server nesting is limited to 32 levels; Oracle supports recursion until stack/memory limits. Ensure transaction handling is consistent across nested calls (SQL Server @@TRANCOUNT, Oracle savepoints).

6Classic Interview Query Problems

1. Find the second highest salary easy
-- A) Subquery
SELECT MAX(salary) AS second_highest
FROM   employees
WHERE  salary < (SELECT MAX(salary) FROM employees);

-- B) DENSE_RANK (generalizes to Nth, handles ties)
SELECT DISTINCT salary FROM (
    SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk FROM employees
) t WHERE rnk = 2;

-- C) OFFSET (returns NULL-less empty set if none)
SELECT DISTINCT salary FROM employees ORDER BY salary DESC LIMIT 1 OFFSET 1;

Use DENSE_RANK, not ROW_NUMBER, so tied salaries count as one rank.

2. Nth highest salary per department / top 3 per group medium
SELECT dept_id, name, salary
FROM (
    SELECT e.*, DENSE_RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk
    FROM employees e
) t
WHERE rnk <= 3;          -- change to = N for the Nth highest
3. Find duplicate rows (e.g. duplicate emails) easy
SELECT email, COUNT(*) AS cnt
FROM   employees
GROUP BY email
HAVING COUNT(*) > 1;
4. Delete duplicates but keep one row medium
-- Works in PostgreSQL / SQL Server (CTE deletes through to the table in SQL Server)
WITH d AS (
    SELECT ctid, ROW_NUMBER() OVER (PARTITION BY email ORDER BY emp_id) AS rn FROM employees  -- ctid: PG row id
)
DELETE FROM employees WHERE ctid IN (SELECT ctid FROM d WHERE rn > 1);

-- Portable alternative: keep the smallest id
DELETE FROM employees
WHERE emp_id NOT IN (SELECT MIN(emp_id) FROM employees GROUP BY email);   -- MySQL: wrap in a derived table
5. Employees who earn more than their manager easy
SELECT e.name, e.salary, m.name AS manager, m.salary AS mgr_salary
FROM   employees e
JOIN   employees m ON m.emp_id = e.manager_id
WHERE  e.salary > m.salary;
6. Departments with no employees / customers with no orders easy
SELECT d.dept_name FROM departments d
WHERE NOT EXISTS (SELECT 1 FROM employees e WHERE e.dept_id = d.dept_id);

SELECT c.* FROM customers c LEFT JOIN orders o ON o.customer_id = c.customer_id WHERE o.order_id IS NULL;
7. Employees earning above their department average medium
SELECT name, dept_id, salary FROM (
    SELECT e.*, AVG(salary) OVER (PARTITION BY dept_id) AS dept_avg FROM employees e
) t WHERE salary > dept_avg;
8. Order count per customer, including customers with zero orders easy
SELECT c.customer_id, c.name, COUNT(o.order_id) AS orders     -- count the RIGHT table's column, not *
FROM   customers c
LEFT JOIN orders o ON o.customer_id = c.customer_id
GROUP BY c.customer_id, c.name;
9. Running total and % of grand total medium
SELECT order_date, amount,
       SUM(amount) OVER (ORDER BY order_date, order_id) AS running_total,
       ROUND(100.0 * amount / SUM(amount) OVER (), 2)    AS pct_of_total
FROM orders;
10. Month-over-month revenue growth medium
WITH monthly AS (
    SELECT DATE_TRUNC('month', order_date) AS month, SUM(amount) AS revenue
    FROM   orders WHERE status = 'DONE' GROUP BY 1
)
SELECT month, revenue,
       LAG(revenue) OVER (ORDER BY month) AS prev_revenue,
       ROUND(100.0 * (revenue - LAG(revenue) OVER (ORDER BY month))
             / NULLIF(LAG(revenue) OVER (ORDER BY month), 0), 2) AS mom_pct
FROM monthly;
11. Consecutive days / gaps and islands (login streaks) hard

Trick: subtracting ROW_NUMBER() from the date gives a constant for each consecutive run.

WITH d AS (
    SELECT DISTINCT user_id, login_date FROM logins
), g AS (
    SELECT user_id, login_date,
           login_date - (ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY login_date)) * INTERVAL '1 day' AS grp
    FROM d
)
SELECT user_id, MIN(login_date) AS streak_start, MAX(login_date) AS streak_end, COUNT(*) AS days
FROM   g
GROUP BY user_id, grp
HAVING COUNT(*) >= 3;          -- users with 3+ consecutive days

For numeric ids use id - ROW_NUMBER() OVER (ORDER BY id).

12. Find missing numbers in a sequence medium
SELECT id + 1 AS gap_start, next_id - 1 AS gap_end FROM (
    SELECT id, LEAD(id) OVER (ORDER BY id) AS next_id FROM t
) x WHERE next_id - id > 1;

-- Portable

           ROW_NUMBER() OVER (ORDER BY salary) AS rn,

    FROM employees

FROM   orders
WHERE  order_date >= '2025-02-01' AND order_date < '2025-04-01'

       FIRST_VALUE(order_id) OVER w AS first_order,
       LAST_VALUE(order_id)  OVER w AS last_order
FROM orders

18. Day-1 retention (users who came back the next day) hard
WITH first_day AS (
    SELECT user_id, MIN(login_date) AS d0 FROM logins GROUP BY user_id
)
SELECT f.d0 AS cohort_date,
       COUNT(*)                                   AS cohort_size,
       COUNT(l.user_id)                           AS returned_d1,
       ROUND(100.0 * COUNT(l.user_id) / COUNT(*), 2) AS d1_retention_pct
FROM   first_day f
LEFT JOIN logins l ON l.user_id = f.user_id AND l.login_date = f.d0 + 1

UPDATE person SET sex = CASE sex WHEN 'M' THEN 'F' WHEN 'F' THEN 'M' END;

FROM   employees e JOIN departments d ON d.dept_id = e.dept_id

HAVING COUNT(*) > 1;
21. Top customer by revenue per month hard
WITH m AS (
    SELECT DATE_TRUNC('month', order_date) AS month, customer_id, SUM(amount) AS revenue
    FROM orders WHERE status = 'DONE' GROUP BY 1, 2
), r AS (
    SELECT *, RANK() OVER (PARTITION BY month ORDER BY revenue DESC) AS rnk FROM m
)
SELECT month, customer_id, revenue FROM r WHERE rnk = 1;
22. Sessionize events (new session after 30 min of inactivity) hard
WITH flagged AS (
    SELECT user_id, event_ts,
           CASE WHEN event_ts - LAG(event_ts) OVER (PARTITION BY user_id ORDER BY event_ts) > INTERVAL '30 minutes'
                  OR LAG(event_ts) OVER (PARTITION BY user_id ORDER BY event_ts) IS NULL
                THEN 1 ELSE 0 END AS new_session
    FROM events
)
SELECT user_id, event_ts,
       SUM(new_session) OVER (PARTITION BY user_id ORDER BY event_ts) AS session_id
FROM flagged;
23. Cumulative distinct users / new vs returning customers per month hard
WITH first_order AS (
    SELECT customer_id, DATE_TRUNC('month', MIN(order_date)) AS first_month FROM orders GROUP BY customer_id
), m AS (
    SELECT DISTINCT customer_id, DATE_TRUNC('month', order_date) AS month FROM orders
)
SELECT m.month,
       COUNT(*) FILTER (WHERE m.month = f.first_month) AS new_customers,
       COUNT(*) FILTER (WHERE m.month > f.first_month) AS returning_customers
FROM m JOIN first_order f USING (customer_id)
GROUP BY m.month ORDER BY m.month;
24. Concatenate values per group (names per department) easy
SELECT dept_id, STRING_AGG(name, ', ' ORDER BY name) AS members FROM employees GROUP BY dept_id;

6.1Concept Interview Questions & Answers

What is the difference between WHERE and HAVING?
WHERE filters individual rows before grouping and can't use aggregates. HAVING filters groups after GROUP BY and can use aggregates. Put non-aggregate filters in WHERE – it's faster because fewer rows get grouped.
DELETE vs TRUNCATE vs DROP?
DELETE removes selected rows (DML, logged per row, fires triggers, supports WHERE). TRUNCATE removes all rows quickly, resets identity, no WHERE. DROP removes the whole table definition and data.
UNION vs UNION ALL?
UNION removes duplicates (extra sort/hash step). UNION ALL keeps everything and is faster – default to it unless you need dedup.
Explain the different types of joins.
INNER = matches only; LEFT/RIGHT = all rows from one side + matches; FULL = all rows from both; CROSS = every combination; SELF = table joined to itself. Semi/anti joins test existence/non-existence without returning right-side columns.
Primary key vs unique key vs foreign key?
PK: uniquely identifies rows, NOT NULL, one per table. Unique: prevents duplicates, allows NULL(s), many per table. FK: references a key in another table to enforce referential integrity.
RANK vs DENSE_RANK vs ROW_NUMBER?
For values 100,100,90: ROW_NUMBER → 1,2,3 (always unique); RANK → 1,1,3 (gap after ties); DENSE_RANK → 1,1,2 (no gap).
COUNT(*) vs COUNT(column) vs COUNT(DISTINCT column)?
COUNT(*) counts all rows; COUNT(col) counts non-NULL values; COUNT(DISTINCT col) counts unique non-NULL values.
IN vs EXISTS? Why does NOT IN sometimes return nothing?
EXISTS stops at the first match and works well with correlated subqueries on large sets; IN compares against a list. NOT IN returns no rows if the list contains a NULL (comparison becomes UNKNOWN), so prefer NOT EXISTS.
What is a CTE, and how is it different from a subquery, view or temp table?
A CTE (WITH) is a named result set valid for one statement – it improves readability and supports recursion. A subquery is inline and unnamed. A view is a stored query saved in the database. A temp table physically stores intermediate data for a session and can be indexed.
View vs materialized view?
A view stores only the query and runs it each time. A materialized view stores the result physically and must be refreshed – faster reads, stale data until refresh.
What is normalization? Why denormalize?
Organizing tables to reduce redundancy and anomalies (1NF → 3NF/BCNF). Denormalization deliberately duplicates data (star schemas, reporting tables) to cut joins and speed analytical reads at the cost of storage and update complexity.
Explain ACID.
Atomicity (all-or-nothing), Consistency (constraints preserved), Isolation (concurrent transactions don't interfere), Durability (committed data survives failure).
What are transaction isolation levels and the problems they prevent?
READ UNCOMMITTED allows dirty reads; READ COMMITTED prevents them; REPEATABLE READ also prevents non-repeatable reads; SERIALIZABLE also prevents phantoms. Higher isolation = more locking/less concurrency.
Clustered vs non-clustered index?
A clustered index defines the physical order of the table's rows (one per table). A non-clustered index is a separate structure with pointers to rows (many allowed). Lookups through a non-clustered index may need an extra key lookup unless the index is covering.
What makes a query "SARGable"? Why does it matter?
Search-ARGument-able: predicates the optimizer can satisfy with an index seek. Wrapping the indexed column in a function (YEAR(col)), arithmetic, or leading wildcards forces scans. Rewrite as range comparisons on the raw column.
How would you optimize a slow query?
Read the execution plan; add/adjust indexes on filter/join columns; avoid SELECT *; make predicates SARGable; reduce rows early; replace correlated subqueries; check join order and statistics; consider partitioning, pre-aggregation or materialized views; verify no implicit type conversions.
What is a correlated subquery?
A subquery that references columns of the outer query and conceptually runs once per outer row. Often rewritable as a join or window function for better performance.
What is the logical order of query execution?
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT (incl. window functions) → DISTINCT → ORDER BY → LIMIT. This is why aliases can't be used in WHERE but can in ORDER BY.
Stored procedure vs function vs trigger?
A stored procedure is a reusable routine that can perform DML/transactions and return results/output params. A function returns a value (scalar or table) and is usable inside queries. A trigger runs automatically on INSERT/UPDATE/DELETE events.
What is a deadlock and how do you avoid it?
Two transactions each hold a lock the other needs, so neither can proceed; the DB kills one as a victim. Avoid by accessing tables in a consistent order, keeping transactions short, using appropriate indexes and isolation levels, and retrying on deadlock errors.
DISTINCT vs GROUP BY?
Both can dedupe. GROUP BY is needed when you aggregate; DISTINCT is simpler for pure deduplication. Optimizers often generate identical plans for plain dedup.
What is a surrogate key vs natural key?
A natural key is a real-world attribute (email, SSN). A surrogate key is a system-generated meaningless id (identity/sequence/UUID) that never changes – preferred in warehouses for dimensions and for SCD2.
What is a star schema? Fact vs dimension tables?
A star schema puts a central fact table (numeric measures + FKs, many rows) around denormalized dimension tables (descriptive attributes like customer, product, date). It's optimized for analytic queries.
Explain SCD Type 1, 2 and 3.
Type 1 overwrites (no history). Type 2 inserts a new row per change with effective dates/current flag (full history). Type 3 stores the previous value in an extra column (limited history).
CHAR vs VARCHAR?
CHAR is fixed-length (padded), good for fixed codes. VARCHAR is variable-length, stores only used characters plus a small length overhead.
What is a self join and when do you use it?
Joining a table to itself with aliases – for hierarchies (employee → manager), comparing rows (pairs, consecutive records) or finding duplicates.
What does the HAVING clause do without GROUP BY?
The whole result is treated as one group, e.g. SELECT COUNT(*) FROM t HAVING COUNT(*) > 10 returns a row only if the condition holds.
How do you implement pagination efficiently?
LIMIT n OFFSET m is simple but slow for large offsets (it scans and discards rows). Use keyset pagination: WHERE id > :last_seen_id ORDER BY id LIMIT n with an index on id.
What are ON DELETE CASCADE / SET NULL / RESTRICT?
Referential actions on parent-row deletion: CASCADE deletes dependent child rows, SET NULL nulls the FK, RESTRICT/NO ACTION blocks the delete.
OLTP vs OLAP?
OLTP: many short transactions, normalized schema, row stores (orders, payments). OLAP: complex read-heavy analytics over large history, denormalized/star schema, often columnar stores (warehouses, lakehouses).
How do you handle duplicates during a data load (idempotency)?
Load into a staging table, dedupe with ROW_NUMBER() on the business key, then MERGE/INSERT … ON CONFLICT into the target so re-running the job doesn't create duplicates.

  • Clarify the schema, grain, and how ties/NULLs/duplicates should be treated before writing SQL.
  • Build queries step by step with CTEs; sanity-check row counts after each join.
  • State the dialect you assume and mention alternatives (e.g. TOP vs LIMIT).
  • Discuss performance: indexes, join order, SARGability, avoiding correlated subqueries.
  • Test edge cases: empty table, all-NULL column, ties, single row, duplicates.
